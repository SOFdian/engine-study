### MESI 协议

为了保证每个 CPU 核心看到的内存数据都是一致的，硬件层面上有一套复杂的通信协议，即 **MESI**。它是四个缓存状态的首字母缩写：

- **M (Modified)** 🔴：数据被我改过了，现在我是唯一的最新版，内存里的都是旧的。
- **E (Exclusive)** 🟢：这份数据只有我有，而且和内存里的一模一样。
- **S (Shared)** 🔵：大家都有这份数据，且都和内存一致。
- **I (Invalid)** ⚪：这份数据已经过期了（别人改过了），我不能再用它，必须重新读取。

### 为什么会产生“乒乓球”效应？

当线程 A 修改位于某个 Cache Line 里的变量 $x$ 时，硬件会自动把其它核心里包含这个 $x$ 的 Cache Line 全部标记为 **Invalid (失效)**。

如果线程 B 正好在另一个核心上修改同一个 Cache Line 里的变量 $y$，它会发现自己的缓存失效了，于是被迫停下来，等待 A 把数据同步过来。接着 B 修改了 $y$，又会导致 A 的缓存失效。

这种缓存行在两个核心之间跳来跳去、互相伤害的现象，就像在打**乒乓球** 🏓，导致 CPU 大部分时间都在等数据同步，而不是在做计算。
