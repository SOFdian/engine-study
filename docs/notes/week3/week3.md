# 第三周学习计划：内存布局与缓存友好

> 依据《52 周引擎岗学习路线》中的“第 3 周：内存布局与缓存友好”进行细化。本周的目标是从底层硬件视角理解代码执行效率，建立数据导向设计（Data-Oriented Design, DOD）的初步直觉。

------

## 一、 本周目标

本周的核心任务是**理解 CPU 如何通过内存访问数据**，并学习如何通过优化数据布局来减少缓存缺失（Cache Miss）。

围绕原路线要求，本周需要完成以下 4 个结果：

1. **结构体实验**：观察 `sizeof` 与 `padding` 变化，编写《内存对齐实验报告》。
2. **性能基准测试**：编写 3 组 AoS（Structure of Arrays）与 SoA（Array of Structures）的性能对比实验。
3. **ECS 架构草图**：设计一个初步的实体组件系统（Entity Component System）风格的数据结构。
4. **验收总结**：能够合理解释为什么连续内存访问能显著提升引擎性能。

------

## 二、 本周学习原则

### 1. 尊重硬件特性

理解“速度”不是一个抽象的算法复杂度（如 $O(n)$），而是受制于缓存命中率、分支预测和指令级并行。在现代 CPU 中，一次 Cache Miss 的代价可能相当于数百条指令的执行时间。

### 2. 测量优于直觉

不要猜测哪种布局更快。必须使用 Benchmark 框架（如上一周接入的 Google Benchmark 或自定义计时器）进行实际测量。

### 3. 数据导向思维

在设计引擎模块时，优先考虑数据的存储和流转方式，而不是先考虑对象层级。

## 三、 第三周详细日计划

### Day 1：内存对齐与填充 (Alignment & Padding)

#### 今天学什么

- **内存对齐原理**：为什么 CPU 访问非对齐内存会损失性能。
- **编译器行为**：`sizeof` 的计算逻辑，`alignas` 与 `alignof` 的用法。
- **结构体重排**：如何通过调整成员顺序减少 Padding 空间。

#### 今天怎么学

1. 编写多个结构体，手动计算其 `sizeof` 预期值，再用 `std::alignment_of` 验证。
2. 实验：对比 `struct { char; int; char; }` 与 `struct { int; char; char; }` 的内存占用。
3. 学习使用 `static_assert` 检查结构体的大小和对齐。

#### 今天的产出物

- 《内存对齐与空间优化实验笔记》。
- `tests/test_alignment.cpp`。

------

### Day 2：CPU 缓存体系结构 (Cache Locality)

#### 今天学什么

- **缓存层次**：L1、L2、L3 Cache 的基本量级与延迟。
- **Cache Line**：空间局部性（Spatial Locality）与时间局部性（Temporal Locality）。
- **预取机制**：CPU 如何猜测你下一步需要的数据。

#### 今天怎么学

1. 阅读关于“缓存友好型编程”的技术博客或《Game Engine Architecture》相关章节。
2. 实验：对比遍历 2D 数组时，“行优先”与“列优先”的性能巨大差异。
3. 使用 `ScopeTimer` 记录不同跳步（Stride）下内存访问的耗时曲线。

#### 今天的产出物

- 缓存行局部性验证代码。
- 绘制一份简单的内存访问步长与耗时的关联图表。

------

### Day 3：AoS vs. SoA 深度实验

#### 今天学什么

- **AoS (Array of Structures)**：传统面向对象风格（如 `vector<Particle>`）。
- **SoA (Structure of Arrays)**：数据导向风格（如 `ParticleSystem` 包含多个 `vector<float>`）。
- **SIMD 友好性**：为什么 SoA 更容易进行向量化优化。

#### 今天怎么学

1. 建立两个场景：一个是处理包含位置、速度、颜色等完整属性的对象数组；另一个是将属性分开存储。
2. 编写 Benchmark 模拟更新 100 万个物体的坐标。
3. 分析在只更新“位置”属性时，SoA 如何通过减少无效数据载入来提升吞吐量。

#### 今天的产出物

- 3 组完整的 AoS/SoA 对比测试用例。
- 初步的性能分析结论。

------

### Day 4：伪共享 (False Sharing) 与缓存一致性

#### 今天学什么

- **False Sharing**：多线程环境下，不同变量位于同一 Cache Line 导致的性能坍塌。
- **硬件干扰**：MESI 协议基础。
- **解决方案**：使用 `alignas(64)` 或填充字节来隔离频繁修改的变量。

#### 今天怎么学

1. 编写多线程实验：两个线程分别高频修改同一个结构体中相邻的两个变量。
2. 测量在没有对齐隔离时，线程竞争导致的性能损失。
3. 应用 `alignas` 优化并观察性能回升。

#### 今天的产出物

- `tests/test_false_sharing.cpp`。
- 实验报告：多线程环境下的内存布局注意事项。

------

### Day 5：数据导向设计 (DOD) 与 ECS 基础

#### 今天学什么

- **DOD 核心哲学**：Where there is one, there are many.
- **ECS 模式**：Entity (ID), Component (Data), System (Logic)。
- **内存连续性**：ECS 如何保证组件在内存中连续存储。

#### 今天怎么学

1. 调研主流引擎（如 Unity DOTS, EnTT）的组件存储方式。
2. 手绘一个 ECS 系统的内存布局草图：如何通过 ComponentManager 管理不同类型的组件数组。
3. 设计一个支持批量更新组件的 System 接口。

#### 今天的产出物

- 《ECS 组件管理数据结构设计草图》。
- 关于“对象聚合”与“数据拆分”的思考笔记。

## 五、 给你的执行建议

1. **利用工具**：除了 `std::chrono`，尝试查阅如何使用 Linux 下的 `perf` 或 Windows 下的 `Intel VTune`（如果条件允许）来观察实际的 Cache Miss 率。
2. **关注 3060 Ti 的背景**：虽然本周偏向 CPU，但理解 CPU 端的内存布局是为了后续能更高效地将数据流式（Streaming）传输到 GPU。
3. **保持平衡**：不要为了极端的 Padding 优化而牺牲代码的可读性，学会识别什么时候这种优化是“过早优化”，什么时候是“核心瓶颈”。
